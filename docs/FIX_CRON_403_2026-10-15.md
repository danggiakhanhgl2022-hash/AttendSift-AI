# AttendSift AI — Sửa Cron 403 trên Vercel (15/10/2026)

## Vấn đề được xác định

- Trình duyệt truy cập `https://attend-sift-ai.vercel.app/api/cron/sync` trả `401` (đúng vì không gửi Authorization).
- Nút **Run** của Vercel Cron trả `403`.
- Trước đây `cloud/app.py` luôn so `request.host` với `CHAMCONG_ALLOWED_HOSTS` **trước khi** kiểm tra `CRON_SECRET`.
- Vercel gọi Cron tới Production Deployment URL; hostname này có thể đổi khi redeploy. Điều này phù hợp với dấu hiệu lỗi `403` hiện tại, nhưng chưa xác minh trực tiếp Host header của lượt Run trên tài khoản người dùng.

## Thay đổi mã nguồn — tối thiểu

1. Tách kiểm tra Bearer token ra thành `cron_authorized()`; yêu cầu secret dài ít nhất 32 ký tự.
2. Chỉ khi `request.endpoint == 'cron'` và Bearer token hợp lệ mới cho phép vượt qua danh sách host. Mọi request khác vẫn kiểm tra `CHAMCONG_ALLOWED_HOSTS` như cũ.
3. Endpoint Cron dùng lại cùng bộ kiểm tra Bearer. Chưa thay đổi đồng bộ, PostgreSQL/Neon, giao diện, bảng công và xuất Excel.
4. Thêm `tests/test_cron_deployment_host.py` để kiểm tra riêng cách xử lý đúng/sai secret.

## Triển khai

- **Phương án dễ nhất:** cập nhật mã nguồn bằng ZIP này lên GitHub; giữ nguyên các biến Vercel hiện có. GitHub commit mới sẽ kích hoạt deployment (nếu Git integration đang bật).
- **Phương án vá nhỏ:** áp dụng file `AttendSiftAI_Cron_403_GitHub.patch` từ gốc repository bằng `git apply ...`; commit và push.
- Không đưa `CRON_SECRET`, `DATABASE_URL` hoặc API key lên GitHub.
- Đảm bảo `CHAMCONG_ALLOWED_HOSTS` bao gồm `attend-sift-ai.vercel.app`; không dùng `*`.
- Chờ Deployment **Ready**, nhấn **Settings → Cron Jobs → Run → View Logs**. Mong đợi `200`; nếu vẫn 403 kiểm tra Deployment Protection/WAF hoặc chính xác response body trong Logs.
- Sau khi thấy `200`, kiểm tra Neon bằng `SELECT COUNT(*) FROM cc_messages;` và so sánh qua các ngày.

## Kiểm thử và giới hạn

- Đã xác minh tính hợp lệ cú pháp Python, bảo đảm phần mã thay đổi chỉ ảnh hưởng xác thực Cron/host; kiểm tra an toàn tĩnh và tính toàn vẹn ZIP.
- Có bài thử Flask mới cho các trường hợp: host Production Deployment thay đổi + token đúng -> 200; host lạ + token sai -> 403; host hợp lệ + token sai -> 401; host lạ + token đúng nhưng route khác -> 403.
- **Chưa chạy test Flask trên hệ thống này** do thiếu Flask/Werkzeug. **Chưa thử Vercel Production thật** và chưa khẳng định lỗi đã hết sau khi triển khai. Các file ZIP và patch không thể tự sửa deployment hiện tại.
